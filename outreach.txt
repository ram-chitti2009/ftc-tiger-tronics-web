Limelight - April Tag pipeline is used to auto allign to the goal and calculate velocity needed for the shooter

Deadwheels - Main method of localization consisting of 3 Gobilda omni-wheels connected to encoders. They allow the robot to measure distance, then with dead wheel calculations, the accurate position of the robot is stored. This localization method was custom programmed to work effectively in TeleOp just as much as autonomous, and it is still compatible with pedropathing. 

April Tags - In autonomous mode, we used AprilTag x values for strafing. To address voltage inconsistencies, especially on the far side, we improved AprilTag detection to reliably score the artificacts, stabilizing performance.


IMU/Gobuilda Pinpoint - Initial method of localization, however, the team decided this was no longer an effective method because it lacked the ability to track external factors. Regardless, IMU is still used to track the angle because there is a smaller margin of error.  This is why we use gobuilda pinpoint for more accurate pedropathing stuff.

Object Detection - Utilizes HuskyLens to detect artificats for better accuracy of intaking balls and to lets is know if we 3 balls or not.

Pathing - After trials with encoder drive, IMU localization, and pure pursuit, the team settled on PedroPathing with custom deadwheel localization for optimal autonomous efficiency, using BezierLines and Bezier Curves commands.

Slide Speed and Torque

PROBLEMS

1620 RPM motors didn’t have enough torque to hang and fully extend with the claw weight 

SOLUTIONS

Both slides switched to 312 RPM motors to lift claw and hang

LESSONS LEARNED

Importance of Quality Assurance (QA) for each  iteration process


Slow and Large Drivetrain

PROBLEMS

Bulky drivetrain caused localization issues

312 RPM motors slowed down drivetrain

SOLUTION

Beveled drivetrain with vertical motors saved space

435 RPM motors increased speed

LESSONS LEARNED

Importance of cautious planning to ensure a smooth building process

Voltage Issues

PROBLEMS

Voltage spikes diminished robot performance

SOLUTIONS

Used a Multimeter to observe when voltage
spikes would occur and figured out that slide
motors were constantly running since encoder
position 0 could not be reached accurately

Observed voltage depressions in the graph

Implemented touch sensor on slides to make
motors stop when slides go down

LESSONS LEARNED

Importance of graphing voltage while robot
runs

Claw Grip

PROBLEMS

Pixels would slip outside of claw’s grip when claw was lifted

SOLUTIONS

Attached rubber bands to claw to create friction

LESSONS LEARNED

Importance of using rubber when picking up plastic pixels

Claw Picking up 3 Pixels and Difficulty Aligning  to Pick up Pixels

PROBLEMS

Claw picked up 3 pixels off stack

Alignment to pixel stack was inconsistent in Auton and Teleop

SOLUTION

New claw with barrier to prevent picking up more than two pixels

Used Husky-Lens AI Camera to detect the stack and align to it

Color sensors in claw to automatically close claw 

LESSONS LEARNED

Importance of evaluating design failures before implementation

Our failure analysis APPROACH

Failure modes and effect analysis (FMEA)

Example of FMEA Approach for Voltage Issue

Severity: Seriousness of effect if failure occurs

Occurence: How frequently failure mode is likely to happen

Detection: How probable current controls will detect the failure mode before it causes a problem

Severity, Occurence, Detection (SOD) Ratings: Assigned ratings on a scale of 1-10, with 10 being the highest in terms of risk or likelihood

RPN (Risk Priority Number) = Severity x Occurence x Detection
